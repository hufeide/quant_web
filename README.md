# QuantLab Pro · 全流程投研平台功能原型

一个**纯前端、零依赖、可离线打开**的投资研究平台界面原型，用于直观感受一个完整投研平台"应该长什么样、有哪些功能"。

- **166 项功能**，覆盖 20 个业务模块：宏观 → 行业产业链 → 大类资产 → 全球外汇 → 股票 / 固收 / 基金 / 期货 / 大宗商品 / 期权 → 多因子 → 策略回测 → 组合风控 → 交易执行 → 数据平台 / 另类数据 / 知识图谱 / 绩效报告，外加 12 项 AI 智能中枢功能。
- **只做界面与功能说明，不实现算法**。所有图表都是种子随机数生成的示意数据；每项功能都配有「功能说明 + 核心指标 + 数据依赖 + 算法实现要点 + 输出与下游 + 关联功能」，可直接作为后续算法开发的需求文档。

## 快速开始

```bash
# 直接双击打开即可（file:// 协议下也能完整运行，无需服务器、无 CDN 依赖）
xdg-open index.html          # Linux
# 或
python3 -m http.server 8000  # 也可以起个本地服务，访问 http://localhost:8000
```

### 界面导航

| 位置 | 说明 |
| --- | --- |
| 顶部搜索框 | 按功能编号、名称、指标名、模块名全局搜索；快捷键 `/` 聚焦，`Esc` 关闭 |
| 左侧导航 | 5 个分组、20 个业务模块 + 「功能全景总表」，数字为该模块功能数 |
| 模块页 | 顶部 KPI 条 → 标签筛选（核心 / AI / 实时 / 风控 / 创新）→ 功能面板网格 |
| 功能面板 | 点右上「说明」或底部「功能说明与实现要点 →」打开右侧抽屉 |
| 功能抽屉 | 完整功能说明、核心指标清单、数据依赖、算法实现要点、输出、关联功能（可跳转） |
| 功能全景总表 | 一页列出全部 166 项功能的编号 / 名称 / 说明 / 核心指标，便于排期对照 |
| URL | 支持深链：`#/m/factor` 打开模块，`#/f/FAC-08` 直接打开某功能说明 |

```

├── FUNCTIONS.md                     功能说明书（4600+ 行，由注册表自动生成）
├── README.md

│   └── js/

│       └── registry/                功能注册表 —— 全部内容的唯一来源
│           ├── 00-core.js           模块目录 + 注册器 F() + 图形工厂 V()

│           ├── 30-allocation-overseas.js  大类资产 8 项 + 全球外汇 6 项
│           ├── 40-equity.js         股票 14 项
│           ├── 45-bond-fund.js      固收 8 项 + 基金 8 项
│           ├── 50-futures-commodity-options.js  期货 7 + 商品 7 + 期权 7
│           ├── 60-factor-strategy.js      多因子 12 + 策略回测 10
│           ├── 70-portfolio-execution.js  组合风控 9 + 交易执行 6
│           └── 80-data-alt-knowledge-report.js  数据 7 + 另类 6 + 知识 6 + 报告 7
└── tools/
    ├── gen-docs.mjs                 从注册表生成 FUNCTIONS.md
    ├── check.mjs                    渲染自测 + 字段完整性 + 关联引用校验
```

**关键设计**：网页和文档共用 `assets/js/registry/*.js` 这一份数据。改功能只改注册表，网页立即生效，跑一次 `node tools/gen-docs.mjs` 文档同步更新，不会出现"文档和界面不一致"。

## 开发与校验

```bash
node tools/check.mjs      # 全部功能的图表渲染 / 字段完整性 / 关联编号存在性
node tools/dom-check.mjs  # 用最小 DOM 桩渲染所有模块页与所有功能抽屉
node tools/gen-docs.mjs   # 重新生成 FUNCTIONS.md
```

当前状态：166 项功能全部渲染通过，498 条功能关联引用全部有效，所有 SVG 坐标在画布内，所有栅格行恰好填满 12 列。

### 新增一项功能

在对应的 `registry/*.js` 里追加一条即可，字段含义见下：

```js
F({
  id: 'EQ-15', m: 'equity', w: 6,        // 编号 / 所属模块 / 栅格宽度(3|4|6|8|12)
  tags: ['核心', 'AI'],                   // 核心→P0，AI/创新→P2，其余→P1
  desc: '一句话定位（卡片上显示，建议 ≤ 60 字）',
  spec: '完整功能说明（抽屉与文档中显示）',
  metrics: ['核心指标1', '核心指标2'],     // 会渲染成卡片底部的指标胶囊
  data: ['数据依赖1', '数据依赖2'],
  algo: ['算法实现要点1', '算法实现要点2'], // 后续开发的技术选型清单
  out: ['输出物1', '输出物2'],
  links: ['EQ-01', 'FAC-08'],             // 关联功能，抽屉里可点击跳转
  viz: function () { return V.line('EQ-15', ['序列A', '序列B'], { n: 60, height: 250 }); }
});
```

`V.*` 图形工厂可用：`line / bar / mbar / stack / hbar / heat / radar / donut / candle / scatter / hist / waterfall / treemap / sankey / network / gauge / band / timeline / table / tgen / list / chat / html`。

## 平台分层

```
┌─ 展示层 ── 投研工作台 · AI 智能中枢 · 功能全景总表
├─ 研究层 ── 自上而下：宏观 → 行业/产业链 → 大类资产 → 全球与外汇
│           分资产：股票 · 固收 · 基金 · 期货CTA · 大宗商品 · 期权衍生品
├─ 引擎层 ── 多因子研究 → 策略研发回测 → 组合管理风控 → 交易执行TCA
└─ 底座层 ── 数据与因子平台 · 另类数据与ESG · 知识图谱 · 绩效归因与报告
```

## 实现路线建议

| 阶段 | 目标 | 建议范围 | 关键前置 |
| --- | --- | --- | --- |
| 一期 数据底座 | 让数据可信 | `DAT-01`~`DAT-07` + `EQ-01/02` + `MAC-01` | PIT 时点库（`DAT-03`）与数据质量监控（`DAT-06`）必须先做，否则后续所有回测结论不可靠 |
| 二期 研究能力 | 让研究可复用 | 各资产模块 P0 功能 + `FAC-01`~`FAC-04` + `KNO-01` | 语义层（`DAT-02`）与因子治理先行 |
| 三期 策略组合 | 让结论可执行 | `STR-01`~`STR-08` + `PORT-01`~`PORT-07` + `EXE-01`~`EXE-04` | 依赖二期的因子与风险模型 |
| 四期 AI 创新 | 让效率倍增 | `AI-*` 全部 + `FAC-10` + `STR-06` + `KNO-05` + `REP-07` | 必须先有治理层 `AI-12` 再放开生成能力 |

优先级分布：**P0 核心 45 项 / P1 完整性 95 项 / P2 AI 与创新 26 项**。详见 `FUNCTIONS.md` 附录 A~E（含 P0 清单、AI 功能清单、被引用最多的 20 个"枢纽功能"、通用口径约定）。

## 说明与边界

- 所有数值、行情、净值、评级均为**示意数据**，由固定种子的伪随机数生成，刷新页面结果不变，便于截图对照。
- 不含任何真实算法实现、不连接任何数据源、不发起任何网络请求。
- 涨跌颜色遵循 A 股习惯：**红涨绿跌**。
- 建议浏览器窗口宽度 ≥ 1280px 以获得完整的多列布局；窄屏会自动降为双列/单列。
